# Perusall Booster — implementation plan

Perusall Booster is a **personal** study aid: a reading-session timer, activity indicators, goals, break
reminders and a local session history. It is **not** connected to Perusall's records. It never reads,
changes, sends or replays anything that Perusall uses for grading, and it never simulates reading.

## 1. Inputs from the analysis

The analysis (kept privately outside this public repository because it contains raw captures, course
identifiers and Perusall's own code) established the facts below. Only these user-relevant, non-sensitive
conclusions are carried over:

| Finding | Consequence for this extension |
|---|---|
| Perusall's official **"Active engagement time"** is measured by Perusall's page and credited by Perusall's server. Its documented rule is "mouse movement or keypress at least once every 2 minutes". | The extension cannot see or reproduce the official number. Every timer it shows is labelled as **personal** and separate from Perusall. |
| Students see no live timer while reading. | A personal timer is a genuine gap the extension can fill. |
| Reading pages live at `https://app.perusall.com/courses/<course>/documents/<document>`. Perusall's API is on a separate origin. | The URL pattern is a stable enough signal to know *whether a Perusall tab is in the foreground*. No access to the API origin is needed. |
| Page markup and script bundles change with every Perusall release. | No content script and no DOM scraping. Integration is limited to the tab URL. |
| Tab visibility, window focus and system idle state are available through standard extension APIs. | Activity indicators use `chrome.tabs`, `chrome.windows` and `chrome.idle` only. |

## 2. Supported functionality

1. **Personal timer**: start, pause, resume, stop (saves), reset (discards, with confirmation). Shows session
   duration and today's total.
2. **Activity indicators** (while a session is running):
   * *Timer elapsed*: time the session was running (not paused).
   * *Perusall in foreground*: the active tab of the focused browser window is on `app.perusall.com`.
   * *Browser focused*: some browser window has focus.
   * *Paused*: time spent paused.
   * *Not determined*: time the extension could not observe (computer asleep or locked, browser closed while
     a session was running).
   None of these is presented as proof of reading.
3. **Goals and reminders**: target session length, daily goal, break reminder every N minutes, notification
   on/off switches, progress bars.
4. **Session history**: start/end, measured duration, foreground duration, paused duration, not-determined
   duration, optional note, completion status. Delete one, clear all, export CSV.
5. **Perusall detection**: the popup shows whether a Perusall tab is open or in the foreground.

## 3. Permissions

| Permission | Why | Not requested instead |
|---|---|---|
| `storage` | Timer state, settings, history in `chrome.storage.local` | — |
| `alarms` | Heartbeat for sleep detection; break and goal reminders | — |
| `notifications` | Optional reminders (user can turn off) | — |
| `idle` | Detect a locked screen, so that time is marked "not determined" | — |
| host `https://app.perusall.com/*` | Lets `chrome.tabs` reveal the URL **only** of Perusall tabs, to decide "Perusall in foreground" | `tabs` (would expose every site's URL), `<all_urls>`, `scripting`, `webRequest`, content scripts |

No content scripts, no remote code, no network requests, no analytics.

## 4. Architecture

```
src/
  shared/        pure logic, no chrome.* (unit-tested)
    timer.ts       timer state machine + accrual of indicator buckets
    time.ts        clock helpers, day boundaries, formatting
    model.ts       types and runtime validation of stored data
    csv.ts         CSV export (with spreadsheet-formula escaping)
    settings.ts    defaults + validation
    perusall.ts    URL matcher for Perusall tabs
    messages.ts    popup <-> background message contracts
  background/    MV3 service worker: owns the timer, listens to tab/window/idle/alarm events
  popup/         popup UI (timer, controls, goals, indicators, today's total)
  pages/         history.html (list, delete, clear, CSV) and options.html (goals, reminders)
icons/           PNG icons (generated by scripts/make-icons.mjs)
tests/           Vitest unit + integration tests (chrome.* mocked)
scripts/         build, manifest validation, secret scan, icon generation, packaging
```

* **Single source of truth.** The service worker owns timer state and persists it to `chrome.storage.local`
  after every change. The popup is only a view. It sends commands (`start`, `pause`…) and renders the state
  it receives back, so closing and reopening the popup can't lose or double-count time.
* **Event-sourced durations.** The state stores *when* the current running/paused segment started, not a
  ticking counter. Durations are `now - segmentStart` added to totals at each transition. This keeps them correct
  when the worker is suspended.
* **Clock choice.** `performance.now()` is monotonic but resets whenever the service worker restarts, so it
  can't persist. The engine therefore uses `Date.now()` with explicit guards:
  * **Backwards clock jumps** (`now < lastObserved`): never subtract; the segment is clamped.
  * **Sleep, suspend, browser closed**: a 30-second heartbeat alarm records `lastHeartbeat`. If the next event
    arrives more than **90 s** after the last heartbeat, the gap is treated as *not determined*. The session is
    auto-paused at the last heartbeat and the gap goes to the not-determined bucket, never to elapsed time.
  * **Screen locked** (`chrome.idle` = `locked`): counted as *not determined* while it lasts. The timer keeps its
    run/pause state; the user decides.
* **Indicator accrual.** On every context change (tab activated, URL changed, window focus changed, idle
  state changed, heartbeat) the elapsed interval since the previous observation goes to the bucket(s) that
  applied during that interval. The intervals are tracked separately, so they never double-count.

## 5. Data storage design (`chrome.storage.local`)

| Key | Content | Limits |
|---|---|---|
| `timer` | `TimerState`: status (`idle`/`running`/`paused`), session id, timestamps, bucket totals, last context, last heartbeat, reminder bookkeeping | one object |
| `sessions` | `SessionRecord[]`: id, startedAt, endedAt, elapsedMs, foregroundMs, focusedMs, pausedMs, undeterminedMs, segments (for daily totals across midnight), note (≤ 500 chars), status (`completed` / `ended-early` / `interrupted`) | newest 1000 kept |
| `settings` | `Settings`: goals, reminder interval, notification switches | one object |
| `schemaVersion` | number | — |

* All reads are validated. Invalid entries are dropped and invalid objects are replaced with defaults, never
  passed to the UI. A corrupt `timer` is saved under `timer_corrupt_backup` before being reset.
* Write failures (for example, quota exceeded) are reported to the popup as an error banner, not swallowed.
* Never stored: URLs, page titles, document names, course names, Perusall identifiers, annotation text, cookies.

## 6. Testing strategy

| Level | What | Tool |
|---|---|---|
| Unit | timer transitions, duplicate-command idempotence, accrual buckets, sleep gaps, backwards clock, midnight splits, daily totals, CSV escaping, validation | Vitest |
| Integration | background message handlers + storage + alarms with an in-memory `chrome` mock; popup reopen; restart recovery; storage failure | Vitest |
| Static | `tsc --noEmit`, ESLint, manifest validator (MV3, permission allowlist, referenced files exist) | npm scripts |
| Security | secret / PII scanner over tracked and staged files | `scripts/check-secrets.mjs` |
| Browser smoke | load the built extension in an isolated Microsoft Edge profile and confirm the service worker and popup load, without touching Perusall | `scripts/smoke-edge.mjs` (if the browser allows `--load-extension`) |

Local mock page: the Perusall URL matcher and foreground logic are tested against mocked tab objects for
`app.perusall.com` and look-alike hosts. The extension never sends anything to the live site.

## 7. Known limitations

* The extension's numbers are **not** Perusall's numbers and cannot predict a grade.
* "Perusall in foreground" means the tab was active in the focused window, not that the student was reading.
* `chrome.idle` reports system-wide input. Once a user is idle for 60 s or longer it can report `idle`, and the
  timer **does not** pause automatically on `idle` (only `locked` is "not determined"). Reading without touching the
  mouse is normal.
* Service workers can be stopped at any time. Sleep is detected within one heartbeat (30 s granularity), and the
  90 s threshold may misclassify an extremely overloaded browser as asleep.
* Chrome only allows alarms every 30 s or more, so reminders can fire up to about 30 s late.

## 8. Features that cannot be reliably implemented (and won't be)

* Showing Perusall's official active engagement time live. It's computed server-side and isn't exposed to students
  while reading.
* Knowing whether the student is actually reading or understanding.
* Anything that changes Perusall's records: synthetic input, keep-alive, request replay or modification, hiding
  Perusall UI. These are excluded by design.
